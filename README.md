# AulaConecta – Front-end

## 1. Descripción del proyecto
AulaConecta es una plataforma pensada para que estudiantes y docentes centralicen en un solo lugar el material de clase, las entregas y los avisos de un curso, evitando que la información quede dispersa en distintos chats y correos.

## 2. Problema que resuelve y objetivo del front-end
Actualmente la comunicación entre docentes y aprendices se dispersa en varios canales (WhatsApp, correo, papel), lo que provoca que se pierdan avisos y entregas. El objetivo de este front-end es ofrecer una interfaz simple y clara donde el estudiante pueda ver sus cursos, materiales y fechas importantes desde un mismo lugar.

## 3. Alcance inicial
En esta primera etapa se planea construir:
- Página de inicio / landing con la presentación del proyecto.
- Página de listado de cursos.
- Página de detalle de un curso (materiales y avisos).
- Módulo de inicio de sesión (solo interfaz, sin autenticación real todavía).

## 5. Ruta tecnológica prevista
El desarrollo del front-end se construirá progresivamente con:
1. **HTML** — estructura semántica de las páginas.
2. **CSS** — estilos, diseño responsivo y coherencia visual.
3. **JavaScript** — interactividad básica (navegación, validaciones).
4. **React** — componentización y manejo de estado de la interfaz.

Por ahora solo se deja documentada esta ruta; el código aún no se desarrolla.

## 6. Acuerdo de trabajo del equipo
- **Rama:** no se trabaja directamente sobre `main`. Toda actividad se realiza en ramas específicas (por ejemplo `feature-presentacion`) creadas a partir de `main`.
- **Revisión:** ningún cambio se fusiona sin que otra persona del equipo lo revise y encuentre al menos una observación real de mejora.
- **Mensajes de commit:** deben describir la acción realizada (ej. `docs: agrega conceptos y flujo de trabajo Git`). No se aceptan mensajes como "cambio", "listo" o "prueba".

## 7. Criterios de calidad para fusionar una contribución
Antes de fusionar cualquier cambio a `main`, debe cumplir:
1. El contenido responde exactamente a lo solicitado, sin dejar secciones vacías.
2. El mensaje de cada commit explica con claridad qué cambió.
3. No contiene contraseñas, tokens, datos personales ni archivos sensibles.
4. Fue revisado por otra persona del equipo, quien registró al menos una observación concreta.
5. La observación de revisión fue corregida y esa corrección quedó en un commit nuevo y visible.
